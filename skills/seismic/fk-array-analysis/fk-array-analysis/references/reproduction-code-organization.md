## 复现类任务的代码组织（用户要"审核代码"时）

复现论文时用户的标准要求是"**用原始脚本跑一遍，再用 Python 跑一遍对比结果**"——两套实现各自
独立跑通、结果互相验证。送审/交付前按**实现路线**分文件夹（不是按脚本类型混放），根目录只留
结果图、复现笔记和过程图脚本：

```
4_fk_analysis/
├── fk_code_octave/   # 路线 A：Seizmo fk4d（Octave 跑原始 .m，慢度扫描在 fk4d 内部完成）
│   ├── README.md
│   └── run_fk4d_*.m
├── fk_python/   # 路线 B：Python Bartlett（自带网格扫描 + 波束形成）
│   ├── README.md
│   └── 预处理 / 引擎 / 检验 / 绘图 四类 .py
└── 根目录：结果 PNG、FK_reproduction_notes.md、过程图脚本
```

### README 对照表与参数清单
- README 必须含一张"**脚本 → 输入数据 → 相位窗(绝对时间) → 方法/参数**"对照表，加一份两套共用的
  参数清单（SMAX/SPTS/FRNG/窗/显著性判据）。审核者是逐脚本核对参数，表格远比散文有效。
### 每步都要有可人工核对的产物（编号阶段目录；脚本与产物同目录）
- ⚠️ **每步都要有可人工核对的产物，且脚本与产物同目录**（用户硬要求，两次强调"每一步都要有输出
  文件可以检查"、"把对应的脚本放到相应的路径文件夹下"）：流水线按**编号阶段目录**组织
  （`01_geometry/`、`02_forward_synth/`、`03_fk_input/`、`04_inversion/`、`05_comparison/`），
  **每个阶段的脚本就放在该阶段目录里**（不是脚本集中一处、数据集中另一处），同目录再放本步
  `log_*.txt`，最后由一个独立脚本出**逐步 PASS/FAIL 核对报告**（文件齐全性 + 数值自洽性 + 逐例判据）。
  脚本内一律绝对路径 ⇒ 拆步/搬家后仍可直接运行；一步只干一件事（"几何+正演"这类合并脚本要拆开，
  后一步只读前一步写下的中间文件）；跨步共用的实验定义（真值/窗/网格）只写一处、各步都读它。
  **每一步还要有"本步的图或表"**（用户追加要求："每一步的输出画个图表示，或者用表格"）——
  记录剖面/散点/柱状，或渲染成 PNG 的参数表，绘图脚本同样放该阶段目录，README 步骤表带一列
  "本步图表（图/表）"；结果主图与诊断图分开命名，不要挤在一张图里。
  ⚠️ **同一份数据不要在两个阶段各出一张图**：用户会直接问"3 和 4 是不是一个波形？"——后一步若只是把前一步的数据再画一遍（或画它的切片），就把图只留在**产生**它的那一步、后一步退回**纯数据步**（本项目实测：`04_fk_input/` 改成只写切窗 SAC + `windows.csv`，图留在 `03_processing/`，并删掉自己那张重复图）。每阶段只画"这一步新产生的量"，否则交付摘要会花时间解释两张同源图。
  用户说"**把流程定好**"时要交的就是这套：README 的"脚本 → 输入 → 产物（数据/图/表）"步骤表
  + **一张流程总图**（盒图逐步列 脚本/输入/产物 + 公共口径；本项目 `09_paperchain_forward/07_flow/plot_flow.py`）。
### 一步只干一件事 / 公共样式模块的 import 层级 / 两套共用预处理
  ⚠️ **一步只干一件事**：生成全长波形（`02_forward_synth/`）与切窗（`04_fk_input/`）必须拆成两步
  ——合成脚本顺带写 `*_win.sac` 会把它塞进生成目录，下游分不清哪份是真的 F-K 输入（本次实测留下
  56 个 SAC 里一半是重复切窗产物）；交付前按"目录里该有几个文件的整数倍"核一遍数量。
  ⚠️ **`import` 公共样式模块的路径层级**：脚本改成按阶段目录放之后，`sys.path` 要插**两级之上的
  那个含 `_pubstyle.py` 的目录**（`dirname(dirname(HERE))`），只插一级会 `ModuleNotFoundError:
  _pubstyle`——每个阶段脚本都要单独跑一遍确认能 import，别只跑第一个。
- ⚠️ **预处理脚本（写 F-K 输入 envelope 的那几个）是两套共用**：归到任一侧都要在 README 写明
  "本套与另一套使用完全相同的输入文件"，否则审核者会误以为两侧预处理口径不同、对比不成立。
### 移动脚本前先确认绝对路径
- 移动脚本先确认脚本内部一律用绝对路径（BASE/OUT 硬编码）→ 可随意 `mv` 进子目录仍能直接运行；
  但 README 要写明运行时用**新路径**，避免照旧命令找不到文件。
### 用户并行重排目录后按"核实→改全→重跑"同步
- ⚠️ **用户在他那边并行重排了目录（改编号/挪层）时按"核实→改全→重跑"三步同步**：① 先 `find <父> -maxdepth 2 -type d`
  列**实际**树（文档常还是旧结构）；② 每个脚本的**多类产物输出根都要改**（台站信息 + 数据拷贝 + 图往往在同一个脚本里，
  只改图那条→脚本继续往旧路径写、**被清掉的老目录原地复活**）；③ 从新位置逐个重跑（`dirname` 层数必错一层），
  再 `ls` 确认旧目录没被重建、产物落在新位置。用户说"**这张图不要**"时**连生成它的代码段一起删**
  （只删文件，下次重跑它又回来；删前 `grep -n` 确认锚点唯一，删后重跑 + `find '*<图名>*'` 为空）。
  完整协议与实测踩坑见 `seismic-paper-reproduction/references/reproduction-work-conventions.md` §4a。
### 代码 / 产物分层定稿（根目录只留入口）
- **代码/产物分层定稿**（用户："fk 下的代码文件太多了，你整理一下"）：根目录只留**入口脚本**
  `run_fk.py` + `README.md`；出图脚本 → `plots/`；图件 → `figures/`；笔记/md/教程 → `docs/`；
  一次性试验（及其产物目录）→ `tests/`；F-K 波束输出 → `fk_code_octave/output_data/`；
  输入 SAC（`envelope_lp_*`）留在原处（下游脚本硬依赖，别动）。出图脚本的 `savefig` 一律改成
  `figures/`，做到"输出即归档"，否则脚本继续往根目录写、整理立刻白做。
### 挪动前 grep 引用，分清两类路径依赖
- **挪动前先 grep 引用，分清两类路径依赖**：脚本内**硬编码绝对路径**（`BASE=...`）→ 随便挪，零影响；
  用 `os.path.dirname(os.path.abspath(__file__))` 定位的（入口脚本、写 pptx 的脚本）→ 挪一层就要改
  （`dirname` 再套一层）。改完**必须实跑验证**：入口脚本 `--only plot` 跑通 + 至少一个被挪的出图脚本
  跑通，再 grep 一遍"还有谁往根目录写"收尾；只 `mv` 不验证 = 断链留到下次用的时候才发现。
- **顺手把结构写死成文档**：给该目录加 `README.md`（目录树逐项一句话作用 + 数据流
  `raw SAC → remove_response → envelope_lp_* → fk4d → output_data/beam_*.txt → plots/ → figures/`
  + 参数表"要改什么去哪个文件哪个位置" + 已知约定/可删的历史重复文件）。
### 命令清单落成 COMMANDS.md；检验脚本归位
- **命令清单要落成文件，不要只在对话里答**：用户会反复问"命令都是啥""在哪个环境跑""要不要切环境"
  ——在 `process_flow/COMMANDS.md` 维护一份分组命令清单（进环境 → F-K → 预处理 → 单台分析 → 剖面；
  附各脚本的开关表 + 环境对照表），并在目录 README 里指向它；路径变了同步更新它。
- 检验脚本（互相关 / 几何 / 峰值显著性）与引擎同属证据链，一并放进对应路线文件夹，不要散在根目录。
### 自包含代码汇总 md（手工维护 + `【注】` 标记）
- **"自包含代码汇总 md" 必须手工维护，禁止用生成脚本**：每条路线一份（如 `FK_octave_code.md` /
  `FK_python_code.md`），内容 = 概述（环境/输入/公共参数）+ **参数区速查** + 每个当前脚本的
  **完整源码（中文注释写进代码里）** + 已退役脚本清单（每个一句"当初干什么 / 为什么退役"）。
  ⚠️ 用户会说"把代码文件用中文注释一下，越详细越好，就改那个 md"——此时**生成脚本会把注释整个
  覆盖掉**（本项目两个"读源文件拼 md"的生成脚本已因此移入 `old_error/`），md 一律手工维护、
  以后也不再重新生成。自己新增的注释统一以 **`【注】`** 开头，与原作者的注释区分开（用户按这个
  标记分辨哪些是整理者写的）；发注释版前 `cp` 一份原始未注释版到 `old_error/`（`*_raw_<日期>.md`）。
### 原作者注释翻译成中文（`【译】`）+ 代码完整性核验
- **原作者注释要"翻译成中文"**（用户会追加这一条，指第三方工具箱源码里那一大段英文注释）：
  约定 `【译】` = 原作者英文注释的中文翻译（Usage/Description/Notes/Version History 段落与
  **每一条行内注释**逐行就地译出），`【注】` 仍 = 整理者自加的解释；`error('...')` 等错误字符串
  **保持英文原样**（那是代码的一部分，改了会变语义）。交付前**必须做代码完整性核验**：把 md 里的
  代码块与原源码都按"每行取 `%` 之前的部分"（跳过整行注释）逐行比对，必须完全一致
  ——2026-09-13 实测 fk4d.m 76/76、fkvolume.m 212/212 行一致才算通过；核验脚本与比对方法记在
  `old_error/` 同批产物旁，别只凭"我只改了注释"口头保证。
### 注释版 md 的行号索引表（改它要保持行数）
- **注释版 md 要带"行号索引表"，且改它时保持行数不变**：用户会问"这个是按照哪个代码讲的/对应多少行"
  ——给的是**你这张 md 自己的行号**（用户明确"行号只需要告诉我你写的这个 md 的对应行号"，不要上游
  工具箱源码行号），做法 = 文末加一张"关键行 → md 行号"速查表（如 `fk4d_source.md` §8.4）。
  ⚠️ **插入/删除都会把其后所有行号整体挪位**：要么同步重算全表，要么把修正**合并进同一行**
  （本次改正一行描述即用此法，`fk4d` 签名 94、`nframes` 264、y 轴递减 674、`p` 677、白化 714、
  波束求和 737、归一 762 全部保持不变）；改完 `grep -n` 复核几个锚点行号再交付。
  （本条针对 md 文档的行号索引表；普通代码 patch 不适用。）
### 被问"我们的脚本和源码有什么区别"的固定框架
- **"我们的脚本和源码有什么区别 / 为什么要做那些修改"按固定框架答，别写散文**：① 先定调
  **算法零改动**（只调 `readheader/readdata/synchronize/getheader/cut/fk4d`，正确性由合成验证背书；
  改了源码就没法声称用的是论文那套工具箱）；② 按 **硬需求 / 科学判据 / 工程便利** 三类列表——
  硬需求 = 不满足源码就报错或用不了（各道同 `b/npts/delta` + 统一公共起点、绝对时间窗、全台共用同一窗、
  R/T 旋转）；科学判据 = 源码只给图不给"峰显著吗"（峰−中值 dB、−3dB 占比、BAZ 合成定标）；
  便利 = 窗参数表 + `TAGS` 过滤、结果文件表头写 method/窗/频带、`conda run -n octave`；
  ③ 最后列**源码有但我们故意不用**的项（`polar`、`weights`、多频带 `frng`、滑动窗、
  `select_fk_peaks`）各给一句理由。这样答既有结构又能挡住"是不是你改坏了"的追问。
### 第三方工具箱源码单独汇总 + 关键公式的中文推导
- **第三方工具箱源码单独汇总进对应路线目录**（如 `fk_code_octave/fk4d_source.md` = 入口 `fk4d.m` +
  它调用的核心 `fkvolume.m` 全量源码 + 依赖函数清单 + 调用签名与 `s4d` 字段说明）。用户说
  "把某函数的源码整理个 md" 时按此结构（入口 + 被调核心 + 依赖清单 + **逐段中文注释**），
  而不是只贴一个函数；注释版末尾再加一节"参数区速查"（窗口定义表 / 选窗判据 / 数值约定清单），
  日后调窗只改参数、不必回头翻源码。
- **注释版源码之后再加一节"关键公式的中文推导"**（用户会说"把公式也推导一下"）：骨架 = 物理直觉
  （平面波 → 台对互谱 → 波束求和，一句话点破"扫描慢度 = 找让所有台对相位对齐的那个补偿量"）
  → 逐式推导 → **代码行 ↔ 公式项对照表** → 分辨率/折叠/混叠等硬约束 → 常见误判（白化稀释、
  亚周期相位对齐）。⚠️ 推导必须按**代码自己的符号约定**逐项推（`r_ij = r_j − r_i`、导向因子带
  `+i2πf s′·Δr`、白化 `cs./abs(cs)` 后只剩相位），结论再用合成定标核对：本项目实测峰值落在
  `s′ = −u/v`（u = 波传播方向）⇒ 峰值矢量**指向震源**、模 1/v，与"fk4d 峰 `atan2(x,y)` = BAZ"
  一致；凭直觉写符号会得出相反结论。成品模板见 `references/fk-principle-explained.md`
  的"逐行对应 + 四项硬约束"一节。
### 两套实现的"方法对比图"
- **两套实现要出一张"方法对比图"**：同一子阵、同一相位窗、同一输入，上下两行（上 = fk4d /
  下 = Python），各自相对峰值 dB + 同一遮罩与标注（峰 ×、理论慢度 +、BAZ 黑线）。结论按
  "两套独立实现同样弥散 = 不是某一套代码的 bug" 表述——这正是用户要求双实现对照的目的。
### 只保留当前链路：`old_error/`、`_superseded/` 清理纪律
- **只保留"当前链路"，迭代过 / 被证伪的脚本进 `old_error/`**：目录按来源分类
  `old_error/{root,fk_python,fk_code_octave,data,logs}`，移动前 `cp` 备份原始 md 与关键数据；
  清理写成一个**可复读的脚本**（把"保留清单"写在脚本里，如 `_cleanup_to_old_error.sh`），
  不要手敲一串 `mv`。⚠️ **只清阶段目录里迭代过的图/脚本时用 `_superseded/<日期>_清理/` + `README_去向.md`**
  （写明"原位置 → 去向 → 怎么搬回来"），并在被清目录的 README 追加"文件去向"一节；用户的标准是
  "留最新这一版 + 一个失败案例 + 一个成功但结论不对的对照"（他的原话就是"迭代过的、失败的、删了"），
  硬删反而要回头解释。清理后**必须重跑一次保留脚本**确认链路仍能跑通，并
  `ls -la --time-style=full-iso` 核对产物 mtime（`/mnt/e` 上被 Windows 看图软件占用会静默不更新）。
### 别在 /mnt/e 上重命名"当前 cwd 所在"的目录
  ⚠️ **别在 `/mnt/e` 上重命名"当前会话 cwd 所在"的目录**：drvfs 会留下断链目录项（WSL 侧显示
  `d?????????`、`ls/stat` 均报不存在，**数据其实完好**，Windows 侧看得到全部文件）——恢复办法 =
  从 Windows 侧改名（`/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe -Command "Rename-Item …"`）
  到**没被缓存过的新名字**（改回旧名仍断）⇒ 移动/改名目录前先 `cd /tmp`、或给每条命令显式传 workdir，
  不要站在待移动的目录里操作。
### 验证通过后收敛为单一实现路线（三件配套 + 历史笔记保留）
- **验证通过后收敛为单一实现路线**（用户："既然现在验证这一套是正确的，那现在就只保留 X 这一套方法流程"）：
  另一套引擎与一次性诊断脚本整批归到 `old_error/<退役名>_<日期>/`（**可恢复、不删**），归档目录里写
  `README.md`（原位置 → 退役原因 → 怎么搬回来）。配套三件事一步都不能省：
  ① **grep 旧产物名确认无残留引用**（`beam_py_*`、`*_results.csv/npy`、引擎探测脚本名、注释里的旧默认值），
  逐文件改干净所有双引擎脚本（出图 / 核对 / 结果表 / 预处理注释）——只删文件不改引用，下次跑就断链；
  ② **同步改 QC 判据里写死的期望值与标签**（`len(rows)==27（3 引擎 × 9 例）`、`判据 A：27/27` 这类断言
  在引擎集合变化后必然 FAIL）——改完**重跑核对报告并逐条看 FAIL 行**，别只看"脚本跑通"
  （实测：删掉一套引擎后期望值 27→18、标签同步，报告才由 27/28 回到 28/28 PASS）；
  ③ README / 代码汇总 md 同步：步骤表里退役那行标"已退役 + 归档路径"，判据表保留历史数值但注明已退役。
  ⚠️ **历史过程笔记保留原样、不随实现退役回改**（复现笔记里另一套实现时期的过程记录是过程证据），
  退役说明只写进归档 README 与 md 的"已退役脚本清单"。
### 用户用代号指代方案时保留两种解读
- **用户用代号指代方案时（如"保留对应的 G"）把两种解读的产物都保留**（G 子阵 / G 窗 ±10 s），别猜着删；
  交付时列一句"按哪种解读保留了什么"请其确认——改动可逆时不要为此打断任务去提问。
### 窗口 / 分量 / 方法 / 频带一律只作参数
- **窗口 / 分量 / 方法 / 频带一律只作参数，不为每个组合另写脚本**（用户原话：窗口"仅需要修改参数，
  不必每个窗口都重新写代码"）：脚本顶部集中一个参数区并注释可选值——
  `PH.TS=struct('A',[...],'B',[...],'G',[...])`、`METHODS={'center','coarray'}`、`TAGS={'G'}`
  只跑某窗（`run('fk_code_octave/export_Tcomp_TS_beams.m')`）；绘图脚本用位置参数选窗/方法
  （`python plot_Tcomp_TS.py BOTH center G`）。新增窗口 = 在参数区加一行 + 在 md 的参数表加一行。
### 参数区必须"完整"+ 枚举维度对齐引擎输入
  ⚠️ **参数区必须"完整"**——连引擎调用行里的数值参数（`SMAX/SPTS/FRNG/WIDTH/OVERLAP/POLAR`、method 列表、
  参考 BAZ）也要提到文件顶部，每个参数一条中文注释写清**含义 / 为什么取这个值 / 改了会怎样**，
  不许留在 `fk4d(d, 100, 0, 35, 201, [0.02 0.25], false, m)` 这类调用行里（用户会直接指出
  "为什么不设置成参数放在前面，再加好注释"）。
  ⚠️ **"只作参数"同样管 Python 汇总/出图脚本，且枚举维度必须与引擎实际输入对齐**：分量集合硬编码在
  循环里（`for comp in ('Z', 'T')`）会让整个分量**静默缺席**——图、CSV、日志都不报错，只是少一整套产物。
  F-K 引擎吃的是 `envelope_0.25LPF/envelope_lp_all_28[_R|_T]`（Z/R/T 三分量，`export_Tcomp_TS_beams.m`
  就是 T-S/T-P × 三分量导出）⇒ 逐分量产物一律写顶部参数 `COMPS = ['Z', 'R', 'T']`、循环用它。
  被问"为什么只有 Z 和 T / R 的呢"时：先 `grep -n "('Z'\|for comp" <脚本>` 找枚举元组（数据多半早就算好、
  只是没画），再提到参数区重跑，别先怀疑数据缺失或去重下数据。
### 数据侧也会缺分量（先 `ls` 确认 R/T 包络）
  ⚠️ **数据侧同样会缺分量：给新子阵/新台组做三分量之前先 `ls -l envelope_0.25LPF/envelope_lp_all_28_{R,T}/`
  确认那几站有 R/T 包络**（本项目 R/T 包络当初只为 G1 七站生成过，G2 八站一直只有 Z ⇒ G2 的三分量
  分析"做不了"根因在此，不是没跑）。补生成时**必须与既有 Z 逐点同网格**（同 `cstart`/`npts`/`dt`，
  `b = LAND_T0`、`o = 0`），否则 fk4d 读 Z 与 R/T 时各台对不齐、静默出错图。
### 频点标签按实际 FFT 栅格写
  ⚠️ **频谱/表格里的频点标签按实际 FFT 栅格写**：`Δf = fs/nperseg`（本项目包络 2 Hz、`nperseg=128` ⇒
  0.0156 Hz，频点为 0/0.0156/0.0469/…），不要沿用旧表的三位小数近似（写过 0.007/0.020/0.050 Hz，实际
  对应 bin 0/1/3）——订正时**改标签、保留原数值**并加一行说明，用户会拿频点与数值对账。
### 重排 / 提参数后做逐字节回归（含 `diff -q` 与备份的坑）
  ⚠️ **重排/提参数之后要做逐字节回归**（重排很容易在改注释时误改逻辑，光"跑通了"看不出来）：
  先 `cp` 旧产物到 `/tmp` → 用同一窗重跑（`TAGS={'G'}`，只花几十秒）→ `diff` 每个产物文件，
  **全部完全一致才算没改坏**；不一致就回头逐行核参数顺序。
  ⚠️ **给脚本新增一个维度（多一个分量/窗口/台站）时用同一次备份自证"只增不改"**：`diff` 原有那批
  行/文件必须**零差异**、文件字节数一致（实测补 R 后 Z/T 的 63 行表里 42 行逐行零差异、Z/T 的 PDF 与
  备份同尺寸；R 是首跑、无基线，不能拿它报"引入差异"）⇒ 否则会把"新增的那一套"误判成"改坏了原产物"
  而回滚。改完照例 `ls -la --time-style=full-iso` 核 mtime（`/mnt/e` 被 Windows 看图软件占用会静默不更新）。
  新增维度同时要**同步文档表与结论行**（产物表加一行 ×R 的图、`实测 N` 表补 R 的列/行、结论里 R 的差异
  与 Z/T 不一致时如实写出来），别只交图不交说明。
  ⚠️ **回归前先确认 `/tmp` 备份里真有那个文件**：`diff -q` 对"备份不存在"也返回非零，与"内容变了"
  同一个退出码 ⇒ 把 `⚠ 有差异` 当回归失败去翻代码是白费一轮。写判据时先 `[ -f /tmp/bak/$f ] || echo 缺备份`，
  只对确实存在的文件做 diff。**某 method/窗的产物若是本次首次生成（此前从没跑过那条分支）就没有基线**，
  不要拿它报"改动引入差异"——结论只能由"改动前已有产物"的那批给出（如 refactor 后 `_center` 四个文件
  逐字节一致、`_coarray` 是首跑），再用"两者共用同一循环、只差入参"补足论证。
### 同一引擎目录里的 .m 一次做成同一形态
  ⚠️ **同一个引擎目录里的 .m 要一次做成同一形态**（参数区在顶 + 逐段中文注释）：用户会追加
  "把另外两个也注释一下看看"——别只注释主脚本，`export_Tcomp_TS_beams.m` / `export_beams_cb_orig.m` /
  `run_fk4d_bandscan_G1.m` 三个都按同一套写法过一遍（各脚本用途/参数/产物对照见
  `references/octave-seizmo-fk4d.md`）。
### "做一个 X 的版本我看看"：变体开关 + 后缀，不污染正式产物
- **用户说"做一个 X 的版本我看看"时的输出约定（试验变体不得污染正式产物）**：
  在原脚本上加**默认关闭的开关**（参数区 + `argparse`，如 `--only STA` / `--env-smooth 0` /
  `--out-suffix _nosmooth` / `--figs <图型>` / `--skip-resp`：不重写去响应 SAC 等上游产物），
  **默认行为一字不改**；变体产物一律走**新文件名（后缀）**——包络 npz 与图件都带后缀，
  **绝不覆盖正式产物**（`sacprocess/envelope/{STA}_envelope_2-8Hz.npz` 是剖面/偏振等下游的硬依赖，
  覆盖它会静默改掉所有下游结果）；**新图型（如"波包显示"）也挂在开关后、默认不出**，
  免得以后跑全站时凭空多出一批图。只跑单台看效果时用 `--only` 收敛范围，别为一张图重跑全站。
  跑完 `ls -la --time-style=full-iso` 核**新产物 mtime 已更新 且 旧产物 mtime 未变**
  （`/mnt/e` 上被 Windows 看图软件占用会静默不更新，脚本照样打印 ✓）；
  ⚠️ **mtime 只能判"有没有更新"，不能推"哪一步先跑"**：drvfs 时间戳会滞后/不更新，用 mtime 排序会
  得出"链式脚本还没跑到那步"的错结论（实测：beams 的 mtime 比 windows.csv 新，其实 fk4d 用的还是旧表）。
  怀疑某步没重跑时看**文件内容**（如 beam 表头的 `true_baz` 是否 = 新真值）或日志，别据 mtime 重跑整链；若保存直接报
  `OSError: [Errno 22] Invalid argument`（同一原因，只是这次硬失败）→ **先 `mv` 旧图到 `/tmp` 再重跑**，
  不要在告警里猜测脚本 bug。
### 用户说"覆盖" = 接受它成为正式版
- **用户看过变体后说"覆盖" = 接受它成为正式版**：去掉 `--out-suffix` 重跑（正式名 = 无后缀），覆盖前照样先 `mv` 旧图到 `/tmp`。
  ⚠️ 此时 `--figs` 里**绝不能带 `bandpass`**——空后缀下它会重写 `sacprocess/envelope/{STA}_envelope_2-8Hz.npz`
  （剖面/偏振的下游硬依赖，被静默改掉）；只列要更新的图型（如 `--figs 1_raw,packet,3_spectrogram`），
  把版式/到时开关（`--xmax/--square/--tt-both/--env-smooth`）一次带齐，跑完逐张核对时间戳与尺寸。
  ⚠️ 1:1 方图实测输出比例 ≈1.00–1.05（`bbox_inches='tight'` 裁边所致），不是精确 1.000，别当 bug 去追。
### "显示波包"图型的做法 + 平滑窗长的连带影响
- **"显示波包"图型的做法**（用户原话"我想让其显示的是波包"）：以**包络为主角**——
  包络**只画轮廓线、不做填充阴影**（`ax.plot(t, env, color='#d62728', lw=1.0)`；早期
  `fill_between(..., alpha=0.30)` 的阴影版被用户否掉，别再默认加填充），2-8 Hz 带通波形
  降为背景（`#999999`, `lw=0.3`, `alpha=0.35`）；纵轴仍取对称 `(-y_max, y_max)`（`y_max` 由波形与
  包络的全局 99 分位一起定标；只从 0 起会把波形负半周切掉）；到时直接用已有的 `arrivals['lines']` 虚线。
  包络口径由 `--env-mode {mean|max|lp}` + `--env-smooth <秒>` + `--env-lp-hz <Hz>` 三个开关控制
  （mean=矩形滑动平均，默认；max=滑动最大值，**严格包住波形**；lp=0.25 Hz 零相位低通=**论文 F-K 口径**），
  ⇒ 同一张图可切平滑/无平滑/保峰/论文低通。
  版式开关同样做成默认关闭的参数：`--xmax <秒>`（横轴上界，默认 T-S+500；用户会指定固定成 0-2000）、
  `--square`（画布宽高比 1:1）——改版式走参数、不新写脚本，产物仍带 `--out-suffix`。
  ⚠️ **平滑窗长同时决定"峰高/峰位"与"理论线是否落在峰上"**：同一 SA18，6 s 平滑时论文式 T-S 落在
  93% 峰高，**3 s 平滑后峰变尖变高（1278.0→1279.6 s）、只到 73%**。用户每次改平滑窗长都要重报这一项。
  ⚠️ **包络线"钻到波形里面"不是画错，是包络后处理本身在压峰**——被问"为什么这个包络不是按照波包来的"时
  按这条答：平滑窗（3/6/8 s）比 2–8 Hz 的振荡周期（0.125–0.5 s）大 20–60 倍，对非负包络再做二次平滑
  ⇒ 峰值只剩波形峰值的 51–64%、约 20% 的时间包络低于 \|波形\|。四口径实测（SA18）/取舍与机制见
  `references/envelope-fk-band-coherence.md` §7，改口径前先读那节，别把"包不住"当成数据或代码问题。
  ⚠️ **归一化因子含包络时，无平滑版的尖峰会撑高 `y_max`、使波形看起来变"瘦"**——这是同一份波形、
  同一归一化口径，不是数据变了；若用户要"包络更毛但波形粗细不变"，把定标改成只按波形算再出一版。
### patch 锚点唯一性 / 程序化删块 / 批量脚本的 `__main__` 保护
- ⚠️ **给已有绘图脚本加代码块前，先确认锚行是目标函数独有的；改完立即做"对象级自检"而不是看脚本是否跑通**：
  同一文件里多个 `plot_*` 函数常含**逐字相同**的循环（如 `for j, (ph, tt, clr) in enumerate(arrivals['lines'])`
  在 `plot_bandpass` 与 `plot_packet` 各有一份），patch 的模糊匹配会命中"第一个"而不是你要改的那个 ——
  报告 success，目标函数却没变（本次表现：新图型的到时线少画 2 条，而图"看着有变化"所以没当场发现）。
  做法：`old_string` 带上**目标函数独有的相邻行**做锚（如 `plot_packet` 版本后面紧跟 `l2 = arrivals.get('lines2', [])`）；
  改完立刻数**图形对象的条数/属性**验证（本例 `ax.lines` 里的竖线应为 6 条而非 4 条、`grep -n <新加标记>` 落在正确行号），
  别只凭"脚本跑通了"或"图看着变了"下结论。
  ⚠️ **同一个"锚点不唯一"的坑在"程序化删块"上会毁文件**：用行切片删掉脚本里一段代码时，锚字符串
  常**同时出现在文件头的 docstring / 文件名注释里**（拿"第一次出现的位置"当结尾标记会把 docstring
  切开、文件被截断重排，语法直接坏掉）——删块前 `grep -n` 确认锚点唯一、或干脆整文件重写；
  任何程序化改写的脚本，改完先 `ast.parse(open(f).read())` 过语法再执行，别写完直接跑。
- **批量脚本必须带 `if __name__ == "__main__":` 保护**（本次实测踩坑）：批量出图脚本（逐台循环出图那种）
  若没这层保护，**校验脚本 `import` 它时会整批重跑**——所有图被静默重新生成、mtime 全变，看起来像
  自己没改对；批量脚本一律把主循环封进 `def main()` + `if __name__ == "__main__": main()`，
  校验另写独立小脚本（或 heredoc）单独复现绘图函数，不要 import 批处理主体。
### 论文 Fig.3 式记录剖面（3 列分量 × 2 行距离轴）
- **论文 Fig.3 式记录剖面（3 列分量 × 2 行距离轴）**：上排 = 震中距 vs 时间（0 = 发震），
  下排 = **陆地段距离 vs 时间（0 = T 波到达大陆坡**，`x = t − ocean/1.48`）；红 = T-P_local、
  蓝 = T-S_local 短竖线（与 Fig.2 同配色，每列都要标相位名）。🔴 **逐台峰值归一化，不用 P98**
  —— 窗内含强 P/S 时实测峰值/P98 = 5.2～7.8，P98 归一化会让每条波形都溢出相邻台站叠成一团。
  台站分布不均时部分波形必然重叠：出图前先算「最小/中位间距 + 间距<2×amp 的对数」并在交付
  说明里如实报告，别默默换布局。到时口径由脚本顶部 `TT_MODE='proj'|'const'` 切换（默认投影走时、
  输出自动加 `_proj` 后缀，恒速版保留原名），下排两轴随口径自动换算成陆地段走时；幅度用**绝对 km**
  参数 `AMP_KM_DIST`/`AMP_KM_LAND`（用户会直接报数，如 50/25）。
  配方、面板口径与自查见 `references/zhou2021-fig3-record-sections.md`。
