## 1. 配方（照抄这 6 条，缺一条结论就不成立）

1. **几何用真实台站坐标**（读 `stations.csv` 的 lat/lon），不用理想三角阵——反演走的就是这条链路。
2. **共享同一个源信号**（一个高斯包络或一段真实包络波形），各台只施加时移：
   `τ_i = −(s·r_i)`，`s = slow·(sin BAZ, cos BAZ)`（**指向震中**）。
   ❌ 每台独立噪声 → 相位不相关、补偿后无法相长干涉 → 合成"假失败"。
3. **F-K 输入形态对齐真实链路**：本例 2 Hz、8399 点、起点 = 发震前 599.951 s、SAC `o=599.951`、
   高斯包络 σ=8 s（0.25 Hz 低通后的包络形态）+ 0.005 白噪声。
4. **窗 = [τ_min − 60, τ_max + 60]**，且判据 `max|τ|/窗长 < 0.7`（本例 0.077-0.290 全 PASS）。
5. **两套引擎共用同一 case 清单与同一慢度网格**：真值/窗/网格写在 `01_geometry/cases.csv`，
   切窗点数写 `03_fk_input/windows.csv`（后者由步骤 3 产出、两引擎都读）；
   网格 `smax = max(35, 1.35×slow) s/deg`、步长 ≈0.35 s/deg（`spts` 取奇）。
6. **case 矩阵含两个方向**：慢度扫描（固定真 BAZ，10→75 s/°）+ 方位扫描（固定慢度，0/90/180/270°）。
   只测"真事件那一组"发现不了象限/方位相关错误。

## 2. 判据与实测基线

| 引擎 | \|Δslow\| max / mean | \|ΔBAZ\| max / mean | bias Δslow / ΔBAZ |
|---|---|---|---|
| Python Bartlett（整窗 FFT + 相位白化） | 0.97 / 0.54 s/° | 5.9 / 1.4° | −0.09 / +0.80° |
| Seizmo fk4d center | 2.68 / 1.07 s/° | 9.2 / 2.8° | −0.10 / −1.44° |
| Seizmo fk4d coarray ★默认 | 2.60 / 0.96 s/° | 10.1 / 2.7° | +0.52 / +1.64° |

⚠️ **fk4d 默认方法 = `coarray`**（用户 2026-09-13 改定，原 center；center 仍一并导出供对照）。

- 判据 A（峰位）`|Δslow| ≤ 3 s/° 且 |ΔBAZ| ≤ 11°`；判据 B（**无系统偏差**）每引擎 bias ≤ 1 s/° / 3°——
  B 才是重点：它直接回答"链路有没有系统性偏移"。
- 诊断量 `beam_at_truth_dB`（真值处波束值 − 峰值，≤0.75 dB 说明真值就在峰内）。
- 误差量级由"7 站几何 + 0.35 s/° 网格 + 峰平坦"决定；**延迟最小的快波例（10 s/°，最大 τ 仅 10.8 s）
  误差最大**（可达 2.7 s/°）——峰平坦时 argmax 不稳，不是链路偏。
- 结论表述：**该方法在此数据上无系统偏差** ⇒ 真实数据测不出相干峰（相邻台互相关 0.06-0.32）不是代码 bug。

## 3. 转换点版正演（消除海洋距离，2026-09-14）——比理想平面波更真的一层检验

当目标震相是**海陆转换后的陆地段传播**（T-P/T-S）时，不要用“从震中方向入射的理想平面波”做正演，
而应该：**取预设转换点 CP**（沿“台阵中心→震中”大圆路径与 **−1000 m 等深线**的交点，项目约定），
**消除海洋距离**（海洋段对所有台相同 ⇒ 台间延迟只由陆地段决定）：`τ_i = (L_i − L̄)/v`，`L_i = |CP→STA_i|`。

实测（Zhou2021 G1，CP=(-32.8651,28.5812)，距 G1 中心 724 km、BAZ=134.6°）：

| 检查 | v=6.0 km/s | v=3.6 km/s |
|---|---|---|
| 互相关实测延迟 vs 注入 τ | 0.031 s | 0.046 s |
| 最近邻台对（100.5 km）\|Δτ\| vs \|ΔL\|/v | 12.74 / 12.75 s | 21.24 / 21.25 s |
| 沿 CP 方位的平面波拟合 | v_app=6.22 (**+3.7%**)，残差 max 2.4 s | v_app=3.73 (**+3.7%**)，残差 max 4.0 s |
| fk4d coarray 反演 | 16.58 s/°@135.9°（−10.5%） | 31.12 s/°@137.7°（+0.7%） |

结论与教训：
1. **有限距离转换点 ⇒ 波前弯曲 ⇒ 平面波拟合的视速度系统性偏高 ~3.7%**（慢度偏低 3.7%），残差随台-CP 距离增大。
   ⇒ 解释“实测慢度 < 平面波预测”（如论文 T-P_local 10.0 vs 13.7 s/°）时，**先扣掉这类曲率/局部性效应**再谈残余差异。
2. **BAZ 可靠（±3°）、慢度不可靠（−10%~+1%）**：慢度偏差跨在“低频 bin 曲率修正值”两侧，
   来源 = 曲率（物理）+ 带内高频相位缠绕（空间混叠）被 dB 域等权平均拉走峰位（与 §25.6 同一机制）。
3. **相位可辨上限 f < 1/(2Δτ)**（本例 0.008–0.013 Hz）：比 0.02–0.25 Hz 分析带低一个量级 ⇒ 该带内多
   数 bin 对这类慢度已混叠，相位斜率只在最低几个 bin 才给出正确慢度。
4. 脚本：`synth_forward/08_conversion_point/{gen_synth_cp.py, run_fk4d_cp.m, check_cp_synth.py}`；
   检查报告 `cp_check_report.txt`、图 `fig_cp_geometry.png` / `fig_cp_synth_check.png`。

## 4. 坑（会静默给出"正确数字 + 错误含义"）

- ⚠️ **注入写错字段不报错、只是没写进去**：判据 = **两组不同参数的注入给出逐位相同的结果**
  （峰位/幅度/prom 全等）⇒ 数据根本没进链路，立刻查字段名与写盘路径；只跑一组会把它误判成
  "注入无效 / 灵敏度不对"，方向就查错了。Seizmo 记录结构的数据字段名见 `land-time-fk.md` §2。
- ⚠️ **两套引擎的峰方位约定差 180°**：Python 引擎（steering 取正号）峰值方位 = `atan2(sx,sy) + 180°`；
  fk4d = `atan2(x,y)`（不加）。**任何跨引擎核对/画图代码都必须带这个偏移**——漏掉会得到 9/9
  "存盘 peak ≠ 结果表"的假报警，且真值诊断点会取到镜像方位（−3~−4.6 dB 的假象）。
- ⚠️ **跨引擎对比前先统一【频带】与【频率合成规则】**（否则会把实现差异误判成"哪套代码更准"）：
  fk4d 把每道**零填充到 2^⌈log2 npts⌉**（`fkvolume.m:256` `nspts=2^nextpow2(npts)`）＋**先转 dB 再对频率
  等权平均**（`mean(s4d.beam,3)`）；Python 常规写法是**原始 npts ＋ 线性功率和 Σ_f P_f**（按能量加权）。
  带内大部分是噪声时（例：σ=8s 高斯包络 96% 功率在 0.03 Hz 以下，而带取 [0.02,0.25] Hz，带内只占 12-17%），
  两者峰位可差 **2-3 s/°**。核定方法：在 Python 里复刻这两条规则后应与 fk4d 存盘**逐值一致**（本例
  10 s/° 12.68@129.4 ✓）；把带收到信号相干段（0.02-0.05 Hz）后两套规则给出**完全相同**的峰。
  ⇒ 报告 fk4d 结果必须同时报频带；真实数据不要用全带结果判断"数据里有没有相干波前"。
  本文实测 Python |Δslow| ≤ 0.97 s/° vs fk4d ≤ 2.68 s/° 的差别**不是**引擎优劣（两者 bias 均 ≈ 0），
  而是上述两条规则所致。诊断脚本：`synth_forward/04_inversion/engine_rule_probe.py`。
- ⚠️ **fk4d 存盘的 `s4d.beam` 本身已是 dB**（实测峰值 ≈ −7.5、中值 ≈ −10.8）：−3 dB 覆盖占比用 `mx − 3`；
  线性口径 `mx·10^−0.3` 会得 0.00%。Python 端 beam 是线性功率（口径不同，别互抄公式）。
- ⚠️ **输入准备路径会动 fk4d 峰位**：在 Octave 里 `synchronize+cut`（读全时段数据、含插值）vs 由 Python
  切窗后写 SAC，同一相位窗下快波/长延迟例的 fk4d 峰位可动 0.9-2.7 s/°（峰-中值仅 3-4 dB）。
  ⇒ 只切窗一次、两引擎读同一份文件；报告里要说明口径。
- ⚠️ **校验注入延迟别用采样 argmax**：σ=8 s 的包络顶部很平，噪声会让 argmax 跳 1-2 个采样（2 Hz → 1 s）。
  用**两两互相关 + 抛物线内插**（本例最大偏差 0.069 s，判据 ±0.15 s）。
- ⚠️ **txt 网格方向**：fk4d 存盘按 (y 行, x 列) 直接 reshape 即正确；用 `np.unique` 升序重建再配数据
  会把 N-S 轴镜像（方位变 `180°−az`）。Python 引擎 `beam[i=东向, j=北向]` 画图要转置。
- **出图必须按期刊规范**（用户会拿 skill 对照检查）：19 cm 双栏宽、600 dpi、**默认只出 PNG**（矢量 PDF 只在用户明确要求、或脚本带 `PDF=1` 时才写）、
  图内**全英文**、标签/图例/刻度 8–10 pt、刻度朝内去上右边框、连续数据 viridis。
  公共样式收进 `synth_forward/_pubstyle.py`（`apply_pub_style()` / `save_pub()`；`savefig.bbox=None`
  保证宽度精确 = 19 cm，用 tight 裁剪会溢出栏宽）。**台站分布图必须用 PyGMT 地理地形图**
  （geo CPT + shading + 海岸线 + −1000 m 等深线 + 经纬刻度 + Elevation 色标；台站黑三角 + 4 方向
  白描边标签）。⚠️ 本地 `@earth_relief_15s` 直读会报 `Cannot find file earth_relief_15s_p` →
  回退 `resolution="01m"`（skill 里的备选方案）；小面板径纬刻度改 5°标+1°小刻。
- ⚠️ **相位白化只压幅度、不动相位，但延迟只能从信号主导的频段里看**：本例带内 |X| 变异系数 2.89 → 0
  （压平），而用**信号主导的低频 bins（0.02–0.03 Hz，3 个）**做相位斜率拟合，Δτ 恢复到 R²=0.9999、
  max|Δ|=0.41 s；**用全带（40 bins 里 37 个是独立噪声）做单对互相关或相位斜率都不行**
  （曾得 +8.7 s vs 真值 −2.84 s）。这与 §25.6 “全带 dB 域平均被噪声段拖动”是同一件事的两面。
  对比图与数据：`synth_forward/05_comparison/plot_processing_compare.py` → `fig_processing_compare.png` +
  `whitened_traces_{tag}.npz`（白化后/切窗后各道 + 频率轴 + 带内索引）。
- ⚠️ **Octave 路径拼接**：`SD = [FK '/synth_forward']` 是 char 不是 cell，写 `SD{1}` 会报
  `sq_string cannot be indexed with {`。
- ⚠️ **换实现先做回归校验**：引擎向量化后与逐格双循环逐点比 `max|Δbeam|/max`（本例 1.9e-15）且峰位索引相同。
- ⚠️ **波束对台站顺序无关，但"道 ↔ 坐标"必须同步重排**：波束是各道白化谱的求和（coarray 是对 i<j
  台对求和），顺序不进入数学——实测把 7 台顺序随机打乱、乃至按震中距重排，峰位完全相同
  （Python `max|Δbeam|/max` ≈ 3e-16；fk4d 三种顺序都给出同一个 25.4178@128.2902）。真陷阱是
  **只打乱数据、没同步打乱坐标数组**；加一个固定自检（打乱 + 坐标同步打乱 → 比 `max|Δbeam|/max`
  与峰位索引）即可永久防住，别靠人眼。
- ⚠️ **送进 F-K 的顺序是台站编号顺序，不是震中距顺序**（用户会直接问"这个是按震中距排序的吧"）：
  顺序不影响结果，但**记录剖面图的纵轴排序是显示口径**（本例按注入延迟 τ 排，与震中距排相关 0.98
  但不等价），两者要在图上/README 里分开说明，别让用户以为 F-K 输入按距离排过。
- ⚠️ **时间轴/零时刻照抄真实链路文件并写进产物**：正演数据的时间基准 = 真实包络产品的
  `starttime / o / npts` **逐项相同**（本例 11:57:38.049 + o=599.951 + 8399 点，t=0 = 发震时刻），
  脉冲中心放在真实 T 波到时附近。⚠️ 切窗后 SAC 的 `o` 变**负值**（`o = −win_lo`，发震在窗起点之前），
  判断零时刻一律算 `starttime + o`，别只看 `b=0` 或文件名。
- 长跑（9 例 × (center,coarray) ≈ 3.5 min）用后台任务 + 日志落盘；Octave `startup_seizmo` 刷大量 warning，
  grep 只看结果行。

## 5. 注入源的**谱**决定峰显著性（2026-09-15 更正，此前的 σ=8 s 窄带源不够）

**根因**：包络信号天生 DC 占优——真实 F-K 输入（2-8 Hz → 包络 → 0.25 Hz 低通）实测 **96-98% 功率在
0.03 Hz 以下，有效带宽 σ_eff ≈ 0.019-0.029 Hz**；σ=8 s 高斯包络更窄（σ_eff ≈ 0.011 Hz）。
所以论文那句“低通 0.25 Hz”**不是有效带宽**，别用“带宽 0.25 Hz ⇒ 分辨率高”去解释别人的图。

**做法（想要“明显的峰值团”就必须这样）**：共享源直接取**真实包络波形**
（如 `envelope_0.25LPF/envelope_lp_all_28/SA18_env_lp.sac`，全长 8399 点、同时间基准），逐台用频域小数延迟平移
（`irfft(rfft(padded)*exp(-2j·pi·f·tau))`，线性平移不循环），再按 cases 切窗 ⇒
**正演输入的谱与真实数据完全一致**，几何/延迟/窗/网格/噪声都不动（单自变量）。

**实测对照**（G1 7 站，同窗/同网格/同管线/同噪声 0.005，唯一变量 = 源谱）：

| 源谱 | 峰-中值 | 主瓣 −3 dB 半径 | \|Δslow\| | \|ΔBAZ\| | −3 dB 彩色面积 |
|---|---|---|---|---|---|
| σ=8 s 窄带（σ_eff 0.011 Hz） | 2.81-3.43 dB | 4.3 s/° | 0.72 s/° | 1.9° | 23-62% |
| 真实包络源（σ_eff 0.026 Hz） | **6.95-8.23 dB** | **1.0 s/°** | **0.23 s/°** | **0.3°** | 0.0-0.1% |
| 真实数据 G1 T-S（参考） | 2.31 dB | — | 峰跑到 4.1@59° | — | 87% |

## 6. 转换点 / 陆地计时正演（T-P_local、T-S_local 的正确几何）

T 波在陆地的相是**从海边转换点辐射的球面波**，不是无限平面波。正演应按：

1. **CP** = 大圆（震中→子阵中心）与 **−1000 m 等深线**交点（`traveltime_profile.get_track(..., ref_el=-1000)`，
   取第一处 ocean→land 交点；本例 CP = (−32.8651, 28.5812)，震中→CP 1631 km）。
2. **海洋段对所有台相同**（Epicentre→CP ÷ 1.48 km/s = 1101.7 s）⇒ 不影响台间延迟；
   **CP 即 t = 0（陆地计时）**：τ_i = L_i / v，L_i = |CP→STA_i|（本例 623-848 km）。
3. 两个真值：陆地 v = **6.0 km/s**（T-P）→ 18.53 s/°；**3.6 km/s**（T-S）→ 30.89 s/°。
4. **窗的选法（被问"这个窗怎么选的"按这三条答）**：陆地计时窗 = `[τ_min − MARGIN, τ_max + MARGIN]`
   （MARGIN ≈ 40 s，覆盖包络的升/降沿），换绝对时间 = `+ t_cp`（本例 1101.7 s）；
   **每个速度例各开一个窗**（6.0 与 3.6 km/s 的到时差 ~70 s，共用一窗会多塞 70 s 纯噪声、稀释波束）；
   判据 = **τ 展布/窗长 < 0.7**（陆地计时的 τ 全为正、带偏移，用 max|τ|/窗长 会得到 1.2/1.65 的**假 FAIL**）。
   本例窗长 117.6 / 142.6 s，展布占比 0.319 / 0.439。平面波那套口径不同（τ 以 0 为中心、±60 s），
   报窗时写明用的是哪一套。
5. 实测（G1 7 站，真实包络源，fk4d coarray）：18.53→19.06@134.3°（+0.53、−0.5°，峰-中值 4.47 dB）；
   30.89→31.08@135.0°（+0.19、+0.2°，峰-中值 4.17 dB）。慢度略偏大来自**波前曲率**
   （近场球面波被平面波拟合，v_app 偏快 ~2-4%），不是引擎 bug。

⚠️ **理论 BAZ 必须先核对台站表**：本例 `stations.csv` 的 `baz` 列（125.93°）实为**未做 cos(纬度) 修正的
平底公式** atan2(Δlon_deg, Δlat_deg)（逐台吻合 ≤0.95°），比真实大圆 BAZ（台→震中，137.26°）**偏西 11.3°**；
而转换点模型给出的来波方向是 **各台→CP 方向均值 134.8°**（中心→CP 137.2°，与真实 BAZ 一致）。
⇒ 检查方法：用 `gps2dist_azimuth(sta, ev).baz` 与表列值逐台对比；偏差异常且接近
atan2(Δlon,Δlat) 时，就是漏了 cos(lat)。用错列值会让正演/反演凭空出现 ~8° 系统差。
脚本与产物：`synth_forward/10_landtime_2case/{01_geometry/step1_cp.py, 02_forward_synth, 04_fk_input,
05_inversion, 06_comparison, 07_flow}`（每步 脚本+日志+数据+图/表）。

## 8. 参数交付清单 & 盲检验

### 8a. 被问"输入 F-K 的参数是什么"一次给全（别只答一半）

- **引擎调用**（`fk4d` 形参顺序）：`fk4d(data, width, overlap, smax, spts, frng, polar, method)`
  —— `width=100`（整窗一次、**不滑动**）、`overlap=0`、`smax`（±s/°）、`spts`（两方向点数 ⇒ 网格
  `spts²`、步长 `2·smax/(spts−1)`）、`frng=[0.02 0.25]` Hz、`polar=false`（**直角**慢度网格，非极坐标）、
  `method='coarray'`；频率维 `beam = mean(s4d.beam, 3)`（`s4d.beam` 已是 dB）。
- **输入数据**：台站数与名单、波形口径（去响应速度 → 2-8 Hz → \|Hilbert\| → 0.25 Hz → 抽到 2 Hz）、
  采样率与点数、SAC 起点与 `o`、**分析窗（绝对时间与陆地计时两套数都报）**。
- **带内频点数 = (f_hi − f_lo) × 窗长**（本例 0.23 Hz × 117.6/142.6 s ≈ **28 / 33** 个独立频点；
  频率分辨率 = 1/窗长）。报频带必须带上这个数，否则读者无法判断平均了几个频点。
- **结论量**：峰 (slow, BAZ) = 全网格 argmax；峰−中值 (dB)；−3 dB 面积占比；主瓣 −3 dB 半径。

### 8b. 被质疑"窗/网格是拿真值定的 ⇒ 拿答案推过程"时：三层说清 + 一次实跑反证

1. **分三层**：① 正演注入用真值（这是正演的定义，不是测量）；② 引擎输入只有 7 道波形 + 网格 + 频带，
   峰 = **全网格 argmax**，改图上的真值标注/标题**不影响 beam 文件**；③ 图上的 τ 三角、灰虚圈（= 理论峰位置）是事后展示。
2. **坦白真实依赖**：主流程窗 = `[τ_min − M, τ_max + M]`，τ 来自**理论 L/v**（转换点几何 + 假定速度，
   与 F-K 结果无关；真实数据也必须这样定窗）；选窗判据（覆盖 + 边距 + 展布/窗长 < 0.7）与具体数值无关。
3. **实跑反证（这步必须做，不要只讲道理）**：换一个"只由理论 τ 范围与慢度量级决定"的**统一窗 +
   统一网格**重跑（本例两例共用陆地计时 [30, 310] s、45 s/° / 259 点），与主流程比对——
   Δslow 差 ≤ **0.07 s/°**、ΔBAZ 差 ≤ **1.8°**、峰-中值反而升高（6.90/5.13 vs 4.47/4.17 dB）
   ⇒ 结论不依赖窗/网格。产物 `10_landtime_2case/08_blind_check/{step1_blind_window.py,
   run_fk4d_blind.m, blind_vs_main.csv}`。
4. **什么才是真循环（明确说自己没做）**：反复调窗/网格/频带直到回收值 = 真值；或在多个候选峰里
   用真值挑峰。反证：同一套参数用于多个不同真值例；回收值仍带 **+2.9% / +0.6% 系统偏差**（没被调平）；
   **同一管线用在真实数据上给出的是错结果**（4.08 s/°@59°）——按答案调出来的参数不可能让真实数据失败。
