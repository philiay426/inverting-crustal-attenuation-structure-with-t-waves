## 工作方式（用户明确要求，2026-09-01）

### 脚本与产物纪律（一个入口 / 只改 ★参数区 / 不自造名词）
- **一个类任务只留一个脚本入口**：换频带 / 换窗长 / 换网格只改顶部 ★参数区（配置表 + `RUN_TAGS` 过滤），
  出图只改一个 plotter 的参数区（`PANELS` / `LAYOUT` / `WSET` / `ERANGE` / `NPEAK` / `THEO`）；
  每迭代一次就另存 `new2/new3` 脚本 + 另一个 plotter + 另一套产物目录是被明确否掉的做法。
  作废的脚本/图集中移入 `_superseded/<主题>/` + `README_去向.md`（旧名→新名逐条对照），不删。
- **不要自造名词、自造概念**：图内文字、图注、口头结论一律用脚本里已有的字段名与措辞
  （`prom` 就是脚本字段，解释时说"峰 − 背景中值"），别给它另起"峰背比 / prominence"这类新名
  （用户原话："不要自己造词造出一个概念"）。
- **并排图是把已有单图搬进一格，不是重做参数**：各格保留各自的窗长 / 频带 / 网格范围，别顺手统一。
- 期刊口径出图（英文标签、面板字母、页脚图例、代码参数名不进图）与出图前的规范自查
  （`scripts/check_fig_text_overlap.py` + `scripts/fig_ink_margins.py`，迭代到相交 0 / 出框 0）
  见 `references/slowness-figure-paper-style.md` §1l；理论慢度点（淡绿十字 + 50% 透明度）与多峰读数见
  `references/peak-reading-and-method-comparison.md` §3 / §6。

- **参数迭代只改 ★参数区，绝不复制脚本**（用户原话："咋又有这么多代码，你换频带直接改参数不就好了"）：
  一个 case 只留一套入口 —— `export_*.m`（★配置区 `C(k)` 结构体数组 + `RUN_TAGS` 过滤）+
  `plot_*.py`（★参数区 `METHOD / LAYOUT(single|wide3) / PANELS / WSET / ERANGE / NPEAK / PEAK_DBAZ / THEO`）。
  换频带、换窗、换网格、换出图组合 = 加一条 `C(k)` 或改一个环境变量/一个常量；
  **不许 beams_newN/ 目录，不许 plot_*_v2.py**。被取代的旧脚本移进 `_superseded/<日期>_<理由>/`
  并留 `README_去向.md`（写清旧→新对应关系与参数），新脚本的 ★参数区里保留同一条配置可复现旧图。
- **出图必须做数值自检（不是肉眼看）**：① 色标在画布内 —— 先 `fig.subplots_adjust(left/right/top/bottom, wspace)`
  再 `fig.colorbar(...)`，然后打印各 `ax.get_position()` 与 `cb.ax.get_position()` 核对不重叠
  （顺序颠倒会让色标压到末格上）；② 慢度显示半宽 = 该格网格半径 `SMAX`、刻度每 10 s/°。
- **PNG/PDF 落 /mnt/e 一律先写 /tmp 再 `shutil.move`**：直接写 drvfs 会报 `OSError 22`（Windows 看图程序
  占着旧文件）或 `OSError 12`（大块缓冲分配失败），也可能静默不更新（脚本打印 ✓ 但时间戳不变）。
- 一窗一带要出"两个能团"（论文 Fig.4 式）时，**先过带宽关**再谈标注：`f_hi ≤ 0.550231/SMAX_需要`，
  往上扩到覆盖 T-P 会丢掉大慢度团；带宽扫对照表、图内多峰标注配方与色标权衡见
  `references/peak-reading-and-method-comparison.md` §6。
- **用户说"不做限制""把尺度调回去"时，先分清是能量还是慢度**：能量 = 色标 dB 范围（`ERANGE`，
  标准 `−0.7…0`），慢度 = 显示半宽/网格半径（各格 `SMAX`）—— 两个独立参数，改一个不会动另一个。
  猜错就得整批重出（漏了问就两个参数一起说明，别自己选一个当默认）。

### 执行方式（只按脚本执行、不抛假设、数值方向先验算）
- **只按脚本/代码执行数据处理，不要自行提出假设、不要发散讨论**：用户原话"不要自己提出假设，
  我只需要你按照脚本或者代码来执行处理数据，不需要你提出问题"。查数据、调参、跑批、如实汇报
  即可；结果异常时给出量化指标（如 max/mean、偏差度）而不是猜测原因。
- 用户对数值/物理量"谁大谁小、方向对不对"的推理错误高度敏感（发现过文档里 1.43 比 1.48 快的
  反向表述、口头把入射角说成能解释视速度偏低）——写任何涉及大小/方向关系的叙述前，用公式或
  代码验算确认方向，不要凭句式接话。
### 被追问参数 / 公式 / 口径时的答法
- **被问"输入 F-K 的参数是什么 / 这个窗怎么选的 / 这不是拿答案推过程吗"时按固定口径答**（用户会连着问）：
  ① 参数一次给全（`fk4d(data, width, overlap, smax, spts, frng, polar, method)` 各值 + 输入波形口径 +
  采样/点数/起点 + 分析窗两套数 + 带内频点数（= 带宽 × `nspts·dt`，`nspts = 2^⌈log₂⌉(npts)`）+ 结论量），别只答一半；
  ② 选窗三条（覆盖全部 τ + 两端留包络时长的边距 + τ 展布/窗长 <0.7），并说明每例各开一窗的理由；
  -  ③ 被质疑循环时按"三层（注入真值 / 引擎盲扫 / 事后标注）+ 坦白窗由理论 τ 定 + **实跑一次统一窗盲检验** +
    说明什么才算真循环"答，别只讲道理。清单模板与盲检验实测见 `references/forward-modelling-calibration.md` §8。
  - **被问"这个参数（窗长 / 网格点数 / SMAX / 频带）根据什么设的、计算公式是什么"时逐条给公式**，
    不能只说"经验值"：窗 = `[min(理论)−30, max+50]`；`Δf = 1/(nspts·dt)`、`nfreq = 带宽×nspts·dt`；
    步长 = `2·SMAX/(SPTS−1)`；**复制峰间距 = `111.195/(f·d_min)`、无混叠上限 `SMAX ≤ 111.195/(2·f·d_min)`**、
    主瓣半宽 ≈ `0.64·111.195/(f·D_km)`；`v = 111.195/s[s/deg]`。公式、G1 实测验证表、逐频带安全上限表
    与判读坑（**峰落在网格边界 =SMAX 不是峰**、CSV 列错位会算出"整齐假脊"）见 `references/fk-parameter-selection.md`。
    ⚠️ **答这类问题只给「公式链」，不要铺例子/表格**（用户会直接发火：“你在那整一堆例子有啥用”）
    ——把**待求量放左边**（如 `SMAX < 0.55/f`，`0.55 = 111.195/(2·d_min)`），再逐项说明右边每个量
    由什么决定（`f` = 频带内的 FFT 频点，由 `频带 + 窗长` 定），最后给一句**联立结论**；
    本案例数字只在**核对**时才补，不在讲解时铺开。
    ⚠️ **比喻也不是退路**（用户 2026-09-20 否掉通俗类比：“为什么总要扯出来新的概念”）：只能用他已经有的参数，
    把每一步**代进具体数字算给他看**（每个字母给 G1 数值与来历），一次讲一步，别引入新符号/新概念。
    他的问法就是“现在失败是不是 X 太小 → 直接告诉我这个量怎么算” ⇒ **先给一句“是/不是”的直答，再给算式**。
    ⚠️ **任何数值都要能追到出处**：用户会问“源码有吗”并拿论文原文反驳（“论文里没看到这个说法”）⇒ 给脚本绝对路径
    （如 `check_mainlobe_coefficient.py`）或论文页码；**自算量必须标“本项目自检项，非论文参数”**
    （主瓣半宽系数 0.64、几何地板 41% 都是这种：概念出自 Rost & Thomas (2002) 的 ARF，数值是我们自己量的）。两个必须主动澄清的点：
    ① **`f` 不是预处理那个 0.25 Hz 低通**——0.25 Hz 是数据带宽上限，`f` 是所选频带内的 FFT 频点
      （`f = k·Δf`），F-K 逐频点各算一张图，**整带 SMAX 由带内最高频决定**；
    ② **SMAX 的公式与窗长无关**（`1/(2·f·d_min)` 由台间距与频率定），但**落到具体频带时必须按本窗的 `Δf` 重算带内最高参与频点**：`Δf = 1/(nspts·dt)`、`nspts = 2^⌈log₂(T/dt)⌉`，窗长一变换参与频点就变、合法 SMAX 跟着变。实测同一名义带 `[0.04, 0.06] Hz`：117 s 窗（Δf 0.0078，只含 0.0469/0.0547）⇒ `SMAX 10.06 / SPTS 59`；141.7 s 窗（Δf 0.0039，含 0.0430…0.0586）⇒ 必须收到 `SMAX 9.39 / SPTS 55` 才不混叠。⇒ **同一串"频带"数字在不同窗长下不是同一组参数**，报参数/写文档时把窗长与 Δf 一起写出来，否则两套数都对却互相"对不上"（用户会拿两处数字对账）。
    ⚠️ **被问"输入波形的采样率哪来的"按三层答**（用户会连着追问"这个采样率哪来的"→"那如果用 4 Hz 呢"）：
    ① **0.25 Hz 是低通截止（数据带宽）、2 Hz 是采样率**（`dt = 0.5 s`），两者别混着说；② 2 Hz 是**脚本参数**
    （链子顶部 `BP=(2.0,8.0); LP=0.25; NEW_SR=2.0`），由 20 Hz 去响应数据**整数抽取 ÷10** 得到
    （obspy `decimate` 要整数倍因子，20/2 正好整除）；③ **换采样率不改 Δf、不改频点**——
    `nfft = 2^⌈log₂(T/dt)⌉` 随 dt 减半而自动翻倍 ⇒ `Δf = 1/(nfft·dt)` 一字不变（143 s 窗：dt 0.5 → 512 点、
    dt 0.25 → 1024 点，两者都是 0.00390625 Hz）。实测 2 Hz vs 4 Hz 重建对照：T-S 带 11.59 → 11.59 s/°、
    单频点 34.79 → 34.54（差 0.7%，来自 ÷10 与 ÷5 两次抽取的滤波细节）、prom 8.91 → 8.91；**只有"无信号配置"
    的峰位会换地方**（T-P 带 0.35@270° → 0.49@225°，正是噪声落点的又一证据）。
    ⇒ 要动频点阶梯只能改**窗长**，改采样率只是把文件与 FFT 各翻一倍、零增益。逐项对照见
    `references/zhou2021-downsample-control.md` §1b。
    ⚠️ **重建链子做变体对照前，先把重建值与既有产物逐点对齐（`max|Δ| = 0`）再下任何结论**：漏掉链子里的
    `bandpass → |Hilbert| → lowpass` 一步，对照就退化成"滤波前 vs 滤波后"（实测差 4 个量级、相关系数 0.05，
    形状已经不像，却差一点被当成"采样率效应"报出）。定位病灶用**分量对照法**：Z 不经旋转 ⇒
    Z 逐点对得上而 T 对不上，问题在旋转/输入；两者都对不上，才是链子写错。
    ⚠️ **被问"这个数字怎么来的"= 要它的计算链，不是要它的含义**（答成解释/意义会被"我是说这个数字怎么来的"打断）：
    单频点峰慢度固定七步照答 —— ① 各台在该 bin 的复谱 → ② 上三角台对互谱 `c_i·conj(c_j)`
    → ③ 每格转向相位 `2πf[(x,y)·r_ij]` → ④ `beam(x,y) = |Σ cs·e^{i p}|²`（存盘已 dB）→ ⑤ 全网格 argmax
    → ⑥ 换算 `|u| = √(x*²+y*²)`、`BAZ = atan2(x*,y*)`、`v = 111.195/u` → ⑦ `prom = 峰 − 全网格中位数`。
    同时报**峰落在网格的哪个位置**：格数 `= u/Δs`、`Δs = 2·SMAX/(SPTS−1)`、半径占比（34.79 s/° 在
    SMAX 42.2 / SPTS 243 下 = 第 ~100 格、半径的 82%）——贴边的峰按"边界伪影"复核，别直接报。
    ⚠️ **低于 `1/T` 那一档（k=1）单独问起时，按"只有合规窗才有一条结果"答**：0.0039 Hz 的周期 256 s ⇒
    **只有 ≥256 s 的窗合法**；143/128 s 窗里它能跑但 prom 只剩 2.4–2.5 dB（等于无峰），114/86 s 窗的 Δf 变粗到
    0.0078 Hz、该档**根本不在频率阶梯上**（"这个频点不存在"不是"测不出来"）。放进 256 s 合法窗后它给
    25.7 s/°@137°（\|dBAZ\| 0°、prom 3.15 dB），同窗 k=2 给 30.5@140°（prom 8.81）、覆盖两档的带
    （含 0.0039/0.0059/0.0078 三档，256 s 窗的 Δf 只有 0.00195）给 27.4@139°（prom 7.86）——三者差值都落在
    k=1 的**主瓣半宽 58.3 s/°**（`Δs = 0.2278/f`）之内 ⇒ 只能报"同量级、不可分辨"，不能挑一个说更准。
    且 256 s 窗里 T-S 波包只占 ~70 s（其余是 T-P 尾波与尾波）⇒ 显著性天然偏低，报数时一并说明。
    ⚠️ **窗长/窗位扫描的解释分两层，别只说"窗短了分辨率低"**：① **合规性**——固定频点后合法窗长下限就是
    `T ≥ 1/f`（0.0078 Hz 需 ≥128 s、0.0039 需 ≥256 s，`1/T` 超过该频点的那几档读数直接作废，不是"更小"）；
    ② **台阵组成变了**——窗起点后移会把**最早到达**的台站切出窗（G1 的 T-S 到时 1272.5/1281.7/1287.1 s 属
    SA18/SA25/SA17，起点挪到 1300 s 后 7 台只剩 4 台）⇒ 孔径与 `d_min` 都变，慢度当然漂。
    归因前先逐窗算"每台理论到时 vs 窗边界"，别把组成效应记在分辨率头上；扫描里**只有方位稳**
    （G1 四窗 137→143°、合法两窗只差 1°）⇒ 结论写成"存在指向震源的相干能量"，慢度不报定值。
    ⚠️ **频带与窗长必须一起选，不能各自独立**：换窗前先在候选窗的 Δf 下**数一遍带内频点**——
    `[0.010, 0.022]` 配 T-P 窗（117 s、Δf 0.0078）只剩 **1 个**频点（0.0156）、配 T-S 窗（141.7 s、Δf 0.0039）才有 **3 个**
    ⇒ 窄带只能用长窗（反之宽带在长窗里能保留更多频点）。用户指定两档频带时默认**每档配它自己那相的窗**
    （b1s↔T-S、b2s↔T-P，= 06 文档的设计配对），换窗要主动说明并给频点数。
    ⚠️ **用户拍板的带即使名义带顶超出判据也照跑（他是甲方），但交付里必须同时给三件**：带内**实际**频点、
    `f_hi`、无混叠复核 `f_hi·SMAX`，以及该带能容下的 `u_max = 0.3225/f_hi`，并在读数表里写清名义带顶哪一头不合规
    （实测：`[0.02, 0.035]` 实际只含 0.0234/0.0312 两档、`u_max 10.32` 与现用带同频点；`[0.005, 0.014]` 与
    现用带的实际频点完全相同 = 0.0078/0.0117）。算法口径/网格仍按目标慢度给（SMAX 17.1 / 42.2），只换名义带边。
    ❌ 两个极端都要避免：拒绍跑（他只是要一份可与现用口径对照的产物）、或默默跑完不标注（事后对账解释不清）。
    带宽取到 0.02–0.25 Hz 时 G1 的整带上限只剩 `±2.2 s/°`（带内 59 频点，详见参考文件 §4 末）。
    ⚠️ **用户只给「大概的窗」并说「具体时间你定」时按四步定死**（他的约束常只给一个方向，如「不要往前定（前面是噪声），
    可以往后顶」）：
    ① **他给的起点是硬下界**，不许往前扩，只能往后加长；上界**不得超过下一震相最早理论到时**（跨相污染）；
    ② **长度必须落在合法阶梯上**：先算 `nsp = 2^⌈log₂(T/dt)⌉`、`Δf = 1/(nsp·dt)`，再数带内**合法**频点（合法 = `f ≥ 1/T`）
       ——坑：100 s 窗 `1/T = 0.010 Hz` 高于带内唯一栅格 0.0078 ⇒ **该组合一个合法频点都没有**（不是「读数不稳」）；
       加到 150 s（`1/T = 0.0067`）才有 0.0078/0.0117 两点；
    ③ 网格按 ② 的 `f_hi` 收：`SMAX ≤ 0.550231/f_hi`（f_hi 0.0117 ⇒ ≤46.95 取 45；f_hi 0.03125 ⇒ ≤17.61 取 17）；
    ④ **回报里把「为什么取这个长度」的算式给全**（窗 + nsp + Δf + 带内合法频点 + f_hi + 合法 SMAX），并写明边界
       （如「带内只剩 1 个合法频点」）；脚本把这几项自检打印（`04_landtime_fk/export_landtime_new3.m` 的写法），别只在回复里说。
       实测（G1 陆地计时）：T-P [60,170]（110 s，上界卡在 T-S 理论最早到时之前）+ 0.020–0.032 ⇒ 2 合法频点；
       T-S [120,270]（150 s）+ 0.005–0.013 ⇒ 2 合法频点。
    ⚠️ **分辨率与无混叠锁在同一根轴上：报参数/报结论时必须一起给"地板"**。联立
    `Δs = C·111.195/(f·D)` 与 `f ≤ 0.5502/SMAX` ⇒ **`f` 被消掉**：`Δs/u ≥ C·2·d_min/D = 1.28·d_min/D`
    （G1 = 41%；若还要求整座主瓣落在网格内，则为 `k/(1−k)` = 71%）。被问"这套几何/参数是不是根本做不了"
    时分三层答：① 分辨两个近邻峰 ⇒ 对，10% 与无混叠数学上不相容，降 f 也救不了（降 f 提分辨率的同时
    上限把 SMAX 压下去）；② 单峰的位置/量级 ⇒ 可以，但精度声明仍受地板约束（不能把"我们 26.3 vs
    论文 24.7 差 6%"读成精度 6%）；③ 论文自身也在这块地板上（T-P 实测 10.0 vs 预测 13.7 差 37%）

### 报峰读数的硬约束（FRNG / 频率合成口径 / 搜索半径 / 原点）
- **报 F-K 峰位必须同时报 `FRNG` 与频率轴合成口径**：带内大部分是噪声时，"频带 + 频率轴合成规则"
  对峰位的影响（2-3 s/°）**不小于**引擎之间的差异——fk4d = 零填充 2ⁿ + 逐频点转 dB 后等权平均，
  Python 常写 = 原始 npts + 线性功率和。⇒ 跨引擎/跨脚本对比前先统一这两项；不能用全带结果判
  "数据里有没有相干波前"（详见 `references/python-fk-implementation.md`、`octave-seizmo-fk4d.md`）。
- ⚠️ **一条带里只要混进一个噪声频点，主瓣就会被"劈成两个团"——见到两个几乎等高的团先拆频点，别当成两个震相/两个转换点**：
  实测（G1 T-S 窗，`FRNG 0.006–0.0131 Hz` 只含 0.0078 / 0.0117 两个 bin）整带图给出 `11.1 s/°@136°` 与
  `45.3 s/°@148°` 两个几乎等高的团；**逐频点单跑**后真相是：0.0078 Hz（唯一合法低频点，Z 与 T 一致）
  = `35.3 / 34.8 s/° @137–138°`（\|dBAZ\| ≤1°、落在搜索半径内），0.0117 Hz 只有 0.3–4.2 s/° 的**随机方位**针尖
  （prom 8–10 dB 但没有方向性）⇒ 两个团都是带平均伪影，**该相的慢度应报单频点值**，不是带平均值。
  做法：对每个 bin 各跑一遍 `FRNG = [f_bin − 0.0005, f_bin + 0.0005]`（bin 位置由 `Δf = 1/(nspts·dt)` 定，
  `nspts = 2^⌈log₂(T/dt)⌉`；低于 `1/T` 的首频点不取），逐 bin 存 `beams_perbin/`，再出「只画合法单频点」的版式。
  ⚠️ **多频点档被稀释时，最快的判据是「三个 method 一致吗」**：同一档读数差一倍以上就是上界频点在稀释——实测
  （G1 陆地计时 T-S T、窗 120–270 s、带 [0.005,0.013] = 0.0078+0.0117、SMAX 45/257）coarray 28.38 s/°@132°
  vs center/full 9.70@136°（prom 5.12 vs 7.32 dB、−3 dB 面积 19.9% vs 14.4%）。此时**只报单频点值**，两件对照缺一不可：
  ① 带收成只留最低合法频点（`FRNG = [带下界, f_low+0.0005]`，SMAX 可放到 `0.550231/f_low`）——实测三方法完全一致
  33.48 s/°@131°、prom 9.1–10.3 dB、−3 dB 10.2%；② 把**相邻相尾波**切掉再跑同一带（窗起点挪到该相理论最早到时之后）
  ——实测 coarray 由 28.38 塌到 8.21 ⇒ 起点前那 20 s 的 T-P 尾在低带上仍有贡献。两者一致才把慢度写进结论；不一致
  按「该档不可判读」报，别挑 prom 高的那个报。
  ⚠️ **方法一致只是必要条件**：公共包络模式（s≈0 针尖）三 method 也会一致——实测 T-P R/Z 在 0.020–0.032 Hz、
  窗 60–170 s 下三方法都报 1.47@45° / 0.98@315°、prom 8.9–11.6 dB，但峰在近零慢度且方位不对 ⇒ 一致之外还要
  峰位落在目标慢度与方位上。同档换窗长读数漂 ~2 s/° 属正常（0.0078 Hz：141.7 s 窗 35.6、150 s 窗 33.5），
  别拿它当「口径变了」的证据。
  判据与频带/混叠侧的推导见 `references/fk-parameter-selection.md` §2c。
- ⚠️ **报峰必须带"是否落在搜索半径内"的检查**：`fk4d` 网格是 ±SMAX 的**方阵**，`\|s\| > SMAX` 的边角格点
  物理上无意义、却常是整带平均后的次高点（本项目实测 Z 分量整带峰 43.8 s/° > SMAX 42.2 ⇒ 边角伪影）。
  逐面板算 `inside = \|s_peak\| ≤ SMAX` 并写进读数表，未通过的不当结果；报数时把 SMAX 一起写出来。
- ⚠️ **峰落在原点时 BAZ 无意义**：`\|s\| < 1 s/°` 的面板不要打印 `BAZ 0 deg`（看着像真方位），
  写 `BAZ n/a (peak at origin)`，那条实测 BAZ 线也别画（零长度）。

  ⚠️ **argmax 不能跨网格半径比较**：网格一放开，全局最大常换到更靠近原点的峰——同一条 T-S 单频点（G2，同窗同带）：±42.2 网格 argmax = `33.13 s/°@127°`，±50 网格 = `17.34 s/°@138°`（\|dBAZ\| 反而更好）⇒ 报数必须写清网格半径，**跨半径的"慢度变了"不是信息**；判源方向峰要用多峰读数（`NPEAK`）或按兄弟子阵最新版那样遮掉反方向 / 原点附近的峰（`MASK=back|origin`）后再看（G1 侧的 28.38 s/° 同样是受限网格下的 argmax）。
  取完**必须用带内实际最高频点复核并报出余量**：`0.01953×25 = 0.488`（宽）、`0.05469×10 = 0.547`（**只剩 0.6%**）
  ⇒ 余量 <1% 时把这句话写进脚本注释：窗长一变短使 `Δf` 变粗、最高频点跳一档就会超限，届时只能把 `SMAX` 收到 9 或把带顶切到 0.0547。
  ⚠️ **多格图里各格 `SMAX` 不同时，页脚必须写明"两格尺度不同"**（用户不会假定同尺度）：每格标题写本格
  `SMAX` 与"裁到多少"，页脚再给一句统口径；想要三格同尺度只能用 min(SMAX) 当共同半宽（其余格多余的半径就被裁掉）。

### 汇报与措辞
- **用户会要求“把失败原因写进汇报”**：交**可粘贴的中文四段式**——① 一句结论（根因是什么，不能是“分辨率不够”这类
  模糊话）；② 分层归因，每条一句 + 一个数字（缺了哪条判据、约束怎么互相冲突）；③ 判据公式块（待求量在左）；
  ④ 参数对照表（失败档 vs 可行档）+“能声称 / 不能声称”的边界（把主瓣宽度、几何地板、论文自身的偏差一起写上）。
  引用自算量时注明“本项目自检项，非论文参数”。
- **用户把汇报幻灯片/摘要里的措辞贴过来问“这么形容如何”时，逐条核四件事**（不是泛泛“看起来不错”）：
  ① **相位与配色对应别写反**（本项目界面图口径：红 = T-P_local、蓝 = T-S_local）——给的建议要写成可直接粘的句子；
  ② 措辞：iasp91/TauP 算出的是**理论走时**（一维参考模型 + 射线理论），写“**真实走时**”会被纠；
  ③ **图上的线用哪套口径，正文里必须写明**：变体图（恒速/双口径）跟文章口径不同的话，
  幻灯片上要标“本图使用 X 口径”，否则读者会以为图上画的就是正文那套（这是 20-25 s 差异的来源）；
  ④ 描述 T-P/T-S 可见性时用**论文的事实句式**——"T-S_local 三分量均可见、以切向 T 最强；
  T-P_local 只见于 Z/R"；别写成“T-P 在 Z/R 有波包、T-S 在 T 有峰值”那种“只在某分量出现”的误读。
  若我们的实测与论文不一致（如本项目 T-P 在三分量都有包络能量），**显式标注“我们的实测 vs 论文”**而不是替论文断言。
